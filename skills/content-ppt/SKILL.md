# Content PPT Pipeline

用于内容优先、重视准确性、证据、结构、信息密度、素材溯源和可编辑交付的演示文稿。

## 运行时与后端合同

- **ChatGPT + CCM**：正式项目执行入口，CCM 提供持久工作区、文件、工具执行和 Git。
- **Codex 原生运行时**：并列的正式入口，使用 Codex 自身的工作区与执行能力，无需 CCM。
- **视觉生成路由**：ChatGPT + CCM 调用 CPA；Codex 原生运行时只调用内置 `image_gen.imagegen`，不调用 CPA。后端不是项目运行时。
- **Content PPT Pipeline**：规定编排、证据边界、生成与审核闭环、PowerPoint 施工和交付规则。

当前任务的用户指令优先于工作流默认规则。

## 核心合同

1. **每轮实际修改前重新核对依据。** 进入当前运行时；重读项目 README/protocol、AGENTS/AGENT、版式/母版权威，以及本轮涉及的原始来源。修改受跟踪文件前检查 Git 状态；按自然材料单元读取，不只依赖聊天回忆。
2. **项目文件是持久权威。** README 管当前入口与接续，AGENTS 管长期规则，canonical 管单页内容和实际未解决问题；详细规范按需读取，不创建平行状态系统。
3. **实际查看证据与参考图。** 不凭文件名、目录、摘要、搜索片段或其他模型描述推断内容。
4. **每页只有一份当前 canonical；需要整页生图时只有一份当前完整页面 prompt。** 局部图件由该页图件权威构造当前完整局部 prompt；纯原生施工不要求虚构生图 prompt。内容变化先改所属权威，同轮同步实际存在的派生输入；除非用户要求，不保留 v2/final/revised 权威分叉。
5. **模型负责生成—目视检查—返工闭环。** 持续推进至达标或实际阻塞，不要求持久维护三类页面状态集合、逐页进度台账或百分比。中断接续只记录必要的当前任务、产物、未完成动作和阻塞。
6. **候选产物与 approved-current 分开。** 新输出须实际视觉审核，文件存在不是过审。生成阶段通过不等于可编辑或用户整套终审通过；可在下游可靠修复的局部缺陷须记录并在交付前关闭。
7. **整页/局部图件每次生成均为独立调用。** ChatGPT + CCM 使用 fresh CPA HTTP request；Codex 使用新的内置 ImgGen 工具调用。整页使用该页 canonical/完整页面 prompt，局部图件根据该页权威形成完整局部 prompt；`prompt` 原文直传，只附本次图件作用域内明确选择的参考图。Codex 只用显式 `referenced_image_paths`，禁止 `num_last_images_to_include`。不从历史聊天、上一页或前次请求会话继承输入。
8. **整页不复用旧生成页，局部图件可按需参考原图。** 旧生成的整页、拒绝的整页产物、Pipeline 图示和演示派生图默认不能作为新整页生图参考。局部图小修改（去字、接口微调）可由 Agent 选择本图件原图；大结构错误或带图越改越乱时不用旧图，从当前权威干净重画。不得跨页混用或无脑递归失败图。
9. **保护证据边界。** 实际项目、实验、装置、测量、结果和现场必须来自可追溯真实来源或真实数据的忠实重建。概念示意和无事实证明职责的通用工程背景允许生成，不能冒充真实记录。
10. **定量证据确定性重建。** 尽可能从数据/代码重绘，不让生成模型重解释精确坐标、数值、图例、色标、不确定度或曲线身份。
11. **只有查明来源或指令缺陷才改 canonical/prompt。** 单次生成图不佳不证明 canonical 有错；运行时失败也不构成科学内容修改理由。
12. **材料核查不能代替成图核查。** 分开执行材料闭合、生成前门禁和实际成图/整套审核；验证工具只读，修复属于明确的施工步骤。
13. **面向观众、以证据解释问题。** 优先真实且已查看的装置/工程素材；正文避免内部代号与无信息的防御性限定，保留真正影响结论解释的边界。
14. **遵守既定版式权威与解释职责。** 用户指定的原生样板优先于生成图的原生版式；每个重要图示关系必须可解释，并支持该页问题和结论。具体施工和保护要求见 ppt-authoring。
15. **按任务选择正确路线。** 第 03 阶段做内容规划与版式选择；全新页面的视觉设计默认走 ImgGen，已有认可设计的原生重建、局部对象编辑、真实数据确定性绘图无需重复生成；用户明确要求纯原生时可直接施工。局部图按几何约束分工，ImgGen 2.5 尽量避免复杂精确三维图。
16. **演讲交付另有显式阶段。** 需要演讲时在现有 PPT 的逐页备注编写讲稿，按目标场合模拟相应观众并分类反馈，再局部修订/复测。答辩评审专家只是一个受众实例，不默认升级科学审计；纯制作/局部修订/无演讲任务跳过不适用步骤。

项目规则可明确调整默认方式；不得无说明地削弱核心合同。

## 动作路由

只加载当前动作需要的参考文件。

| 动作 | 执行职责 | 读取 |
|---|---|---|
| 开始、接续、进展 | 从项目文件、Git 和实际产物恢复当前工作；审核依据不明则重新查看 | runtime + workflow |
| 内容/证据审查 | 核对叙事权威、实验/工况/数据身份、证据角色、数值与统计定义、页面职责、主讲与答疑边界、工作量及跨页一致性 | workflow |
| 内容规划与版式选择 | 确认每页职责、受众需要、版式权威、阅读顺序，决定整页生成/局部图处理/直接原生施工 | workflow + ppt-authoring |
| 材料审计/闭合 | 审查 canonical、prompt、来源索引、数据、派生图和 QA/构建逻辑，完整复查至一轮无新增实质问题 | workflow + runtime |
| 素材查看/选择 | 实际查看真实素材，先判证据角色，再判能否生成、重建或必须保留原件 | workflow + visual-generation |
| 生成前门禁 | 核对 canonical/prompt、参考资格、独立输入和候选输出位置 | workflow + visual-generation + runtime |
| 视觉生成/返工 | 按宿主固定后端只生成需要的页；独立调用、落地候选、逐张实际检查并迭代 | visual-generation + runtime |
| 局部插图重画/去字 | 按几何耦合划分 ImgGen/PPT 对象；Agent 按修改幅度决定是否带本图件原图、使用完整局部 prompt 并独立调用 | visual-generation + ppt-authoring |
| 成图审查 | 对照 canonical、prompt、合格参考，查科学/证据/数值/可读性/版式及相邻页一致性 | visual-generation + workflow + runtime |
| 复用/重建/新增/退休 | 按当前职责、内容、证据兼容性及可确认的当前过审产物决定 | workflow + runtime |
| 可编辑施工/修订 | 从当前产物、canonical、真实素材和原生对象施工；仅在整页 ImgGen 原图转可编辑时要求下一张独立对照页，编辑页独立完整可读 | ppt-authoring + runtime |
| 整套 QA/终审 | 实际渲染连读，核对叙事、事实、公式、证据、可读性、重复/遗漏、可编辑性和交付边界 | workflow + ppt-authoring |
| 逐页讲稿/演讲排练 | 依据已成型的 PPT，在每页备注编写口语讲稿并核对转场、读图与时长 | workflow |
| 独立模拟目标观众 | 在独立上下文仅给目标角色、交付 PPT 与备注，检验实际理解并分级反馈，按需修订复测 | workflow；科研答辩另读 research-defense |

表中名称对应 `references/<名称>.md`。

科研答辩、论文开题/中期/学位答辩额外读取 `references/research-defense.md`。其他任务不自动套用答辩专属规则。

`references/examples/` 仅在用户或项目明确选择时读取，示例不是权威。

每轮实际修订重读当前项目权威和直接相关来源；参考文件在上下文不完整、过时、冲突或不足时重新读取。
