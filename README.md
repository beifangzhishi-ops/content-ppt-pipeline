# Content PPT Pipeline

## 插件图标

插件提供两种尺寸的配套 PNG 图标：`assets/icon.png` 用于 `composerIcon`（256 × 256），`assets/logo.png` 用于 `logo`（1024 × 1024）。`plugin.json` 通过 `extensions.com.openai.interface` 引用这两个资源。安装 ZIP 包含 `plugin.json`、`skills/` 和 `assets/`；`scripts/build-plugin-icon.py` 用于按需重新生成图标资源，使用 Pillow，仅作为构建辅助，不随安装包分发。

面向 ChatGPT 和 Codex 的证据驱动、内容优先 PowerPoint 工作流 Skill，适用于科研答辩、工程报告、课程和技术评审。当前版本：**1.0.0**。

## 正式运行入口

- **ChatGPT + CCM**：CCM 提供持久项目工作区、文件、执行和 Git；ChatGPT 负责推理、研究、编排和审核。
- **Codex 原生运行时**：直接使用 Codex 的原生工作区和工具，与 ChatGPT + CCM 是并列的正式入口。
- **Content PPT Pipeline**：负责内容叙事、证据边界、生成审核闭环、可编辑施工及交付门禁。
- **视觉生成**：ChatGPT + CCM 使用独立 CPA 后端；Codex 直接使用内置 `image_gen.imagegen`，无需 CPA。生成后端不是项目运行时，CPA 和 CCM 均不随本插件打包。

## 演讲引导、版式确定与母版门禁

整套新制先建立跨页的“问题/目标 → 工作与证据 → 结果 → 贡献/创新”对应，逐页规划内容职责。**有演讲任务时，用户决定口头讲什么、讲多少、讲多深、讲述节奏及主讲/答疑取舍**；可以提交提纲、口述或当前 PPT 备注，不要求自己逐页写完整讲稿。Agent 可以建议讲稿，但不得擅自改变已认可的口头内容；由 Agent 设计章节导航、视觉注意力焦点、读图路线和可指认对象，配合用户讲述。

**批量制作整套 PPT 前，必须先完成并经用户确认全套版式：**

1. 按全部已规划页面列出实际需要的版式类型及变体，确定每页归属；统一画幅、字体/色彩层级、标题、页脚、结论区、导航与正文安全区。
2. 实际制作**可编辑 PowerPoint 幻灯片母版（Slide Master）、原生布局（Layout）、占位符和全部类型的可编辑示例页**；固定元素与需要逐页调整的对象正确分层。不是一组截图、整页 ImgGen 背景图或提示词。
3. Agent 对所有版式真实渲染并在目标 PowerPoint 打开、保存、重开、编辑及切换布局验证；把全类型预览和可编辑母版源 PPTX/POTX、示例页交用户。**整套版式获明确认可之后才允许批量制作正文**，不需要逐页确认。
4. 已认可且真正可编辑、覆盖全部类型的模板可直接复用，但需核对逐页映射和有效确认。中途新增版式或改变固定框架，先更新母版并确认受影响的变化，再继续制作；局部页面修订不重启整套门禁。

已确认母版/全部版式映射由项目既有 README/版式入口、每页 canonical 维护，不另建台账。最终成品还须经过独立的整套用户验收，不能用前置版式认可代替。

## 原生优先、按需 ImgGen 与返工

按页/图件质量分流：**新页面默认从已确认的可编辑母版直接原生设计与制作**，按内容、读图路径和审美实际渲染验收；可确定性文字、公式、对齐和对象问题先原生修正。复杂机制/概念图无法合理原生表达时可直接单独生成局部图件；只有整页原生构图明显不合格、难以合理修复或用户明确要求重设计时，才使用 ImgGen 做整页设计并按需原生可编辑重建，不能机械拼框以逃避视觉设计。整页生成时模型推进 `canonical -> 当前完整页面 prompt/参考门禁 -> 独立生成调用 -> 本地候选 -> 实际看图 -> 通过或返工 -> approved-current`，直至达标或实际阻塞。**整页 ImgGen 不得反向替换已确认的母版结构。**

**整页/局部图件的每次生成均为 fresh 独立调用。** ChatGPT + CCM 使用 fresh CPA HTTP request；Codex 直接调用内置 ImgGen。整页重新读取本页 canonical/完整页面 prompt 并原文传入；局部图件从本页当前图件职责形成自包含的完整图件 prompt。**旧生成图禁令仅限制整页生成**；局部概念图去字、接口微调等小改可由 Agent 选择带本图件原图，大结构错误或带图越改越乱时改为不带旧图干净重画。不跨页夹带参考或历史请求上下文。Codex 仅以 `referenced_image_paths` 显式引用本次合格图片，禁止 `num_last_images_to_include`；后端不可用时不自动切换。

不要求持久维护三类页面状态集合或逐页进度台账。候选和当前过审成品仍分开；文件存在、目录名和旧记录不能证明通过。生成阶段通过不等于可编辑验收或用户整套终审通过。

生成前分清三个提示词角色：必须显示的内容、仅指导构图的视觉职责、不得显示的溯源/施工/核查说明。不能用代码擦除、拼接或像素补丁改造权威生成原图；图件局部去字属于**新的独立 ImgGen 图件请求**，不是脚本改写原图。查明来源/指令缺陷才修改 canonical/对应完整输入，否则独立新调用返工。

## 项目入口与接续

每轮实际修改前：进入既有工作区 -> 读 README/protocol 与 AGENTS -> 确认版式/母版权威 -> 读本轮相关原始来源及 canonical/当前 prompt -> 核对实际产物和 Git 状态。

- README 维护当前稿、当前任务、下一步及来源/专项入口，替换失效内容，不写成历史流水账。
- AGENTS 维护长期规则、入口顺序及项目对 skill 的明确覆盖，通用流程引用 skill。
- 每页唯一 canonical 维护事实、页面职责、已确认版式类型及母版映射、素材/图件角色、用户口头重点与视觉指认（有则维护）以及实际未解决问题；只对真正执行的生成任务派生并同步完整 prompt，纯原生路径不虚构 ImgGen 输入。
- 来源索引与专项规范按需读取，不创建重复权威、平行状态数据库或接续日志。

中断时只在现有项目入口记录必要的当前任务/阶段、当前页与候选文件、未完成动作、实际阻塞及下一步。恢复时检查实际产物；审核依据不明则重新查看。聊天历史不作为项目数据库。

## 可编辑 PowerPoint

整套新制以实际原生可编辑的 PowerPoint 母版、布局和各类示例页为施工基础；母版/布局视图能编辑固定框架，正文页可编辑占位符和独立内容对象。需要新增布局或改整套视觉系统时先确认变更，不能无声改变用户已认可的版式。

**整页 ImgGen 原图转可编辑页面时**，将完整生成原图放在对应编辑页之后的**下一张独立对照页**，保留原图媒体字节，供翻页比较。编辑页独立重建可编辑对象并保持完整可读；完整原图只在独立对照页。含对照页的比较工作稿与正式净稿分开说明页数，正式净稿排除对照页。纯原生新制/局部修订不强制生成对照页。

- 用户指定的原生重建样板决定原生版式，生成图不反向覆盖样板。固定页顶/页底/过渡页复用完整原生对象和内部格式。
- 同一语义内容用一个文本框，框内换行和局部格式保留；表格使用原生表格，逐项核对字体、加粗、色彩、水平/垂直对齐、边框、填充与嵌套色块。
- 局部删除/合并按几何、内容及素材角色保护结论、页脚和真实图片，保留已认可对象，避免整页统一组合缩放。
- 科研图保持长宽比和未重绘原件的媒体字节；需调整图框时改布局或从真实数据重绘后等比放置。
- 局部概念图可用 ImgGen 去字，再用 PPT 原生文本框重建可浮动数字/说明；自由箭头等用原生对象，压力表 P、紧贴结构的尺寸示意线等随图件绘制。小改可带本图件原图，结构错或漂移时干净重画；不能从生成页裁取真实科研证据，不能以白块遮字或像素修补伪造重建。ImgGen 2.5 尽量避免复杂精确三维图，优先可信原图/CAD/二维示意。
- Office Math 同时核对符号与数学节点结构；保存重开可有等价 run 分段，不能改变指数、下标、括号、乘子等含义。

先确认全部版式并用真实复杂代表页验证施工方法，再按授权范围扩展。完成目标 PowerPoint 打开、保存、关闭、重开、母版/布局切换和对象编辑检查后才能声称实机通过；验证工具只读，试验用副本，修复走独立施工步骤。

## 内容与证据

实际项目、实验、装置、测量、模拟结果、现场和已命名事实对象使用真实可追溯来源或真实数据忠实重建，禁止生成写实替身。概念机制和不承担事实证明职责的通用工程背景允许生成，包括写实图；标题/图注不得冒充真实记录。

真实素材优先且必须实际查看。精确坐标、数值、图例、色标、不确定度和曲线身份在数据/代码或真实图层保持，不让生成模型重解释。

每页一个主要问题，标题、主证据与结论一致；重要箭头能解释“来源 -> 关系/动作 -> 目标”。先按受众任务规划内容与版式：管理、课程、产品等演示不强制套科研计算链；必要科研公式/变量也不因追求通俗而删掉。正文面向听众，避免内部代号、无信息的防御性文案和机械模板，保留真实必要限定。

科研答辩额外读取 research-defense：已核准新数据增强证据密度和工作量，保留清楚准确的现场表达；必要边界不能因简洁而删除，提示词不能压掉关键推导、基准与证据。

## 门禁与验收

整套新制的**版式/可编辑母版确认**发生在批量正文制作之前；下面的材料、ImgGen 输入、成图及最终整套验收不能代替这道用户确认门禁。

材料闭合、**仅对需要生成的任务**执行 prompt/参考/独立请求门禁、实际成图/整套审核分别执行。材料至少一轮完整复查无新增实质问题；文字 QA、构建或包结构通过都不能代替看图与整套连读。制作 Agent 自主按全图与复杂局部检查层级/对比度/排版/空间，不强制独立 QA Agent 或二轮触发。

生成构图可通过并记录能可靠下游修复的局部问题；科学、证据、结构或核心解释缺陷不能延期。所有待修项在最终可编辑交付前关闭；位图交付不允许延期到不存在的编辑层。

QA/validator 只读。局部修改尽可能对照非目标页和相关媒体/关系，避免旧脚本或验收工具无意改稿。内部整套 QA 后给用户完整稿件终审机会。

演讲任务显式区分**用户口头信息设计 → Agent 视觉引导/辅助维护当前逐页 PowerPoint 备注 → 独立模拟目标观众 → 建议与用户决定口头取舍 → 修订复测**。已有项目的当前 PPT 真实备注（包含未保存的实时用户修改）优先；不从旧独立讲稿反向覆盖。实讲语速优于通用估算，若已含翻页/停顿不重复加时。模拟角色按场合设定（答辩评委、管理层、客户、学生等），不默认升级科学论文审稿；无演讲任务可跳过。

## Skill 分层与打包

核心合同与动作路由在 `skills/content-ppt/SKILL.md`。参考文件分别负责运行时（runtime）、业务工作流（workflow）、双宿主视觉生成（visual-generation）、原生施工（ppt-authoring）和答辩叙事（research-defense）。`references/examples/` 仅在明确选择时使用，不是权威。

在仓库根目录运行：

```powershell
.\scripts\build-chatgpt-zip.ps1
```

生成 `dist/content-ppt-pipeline-chatgpt-upload-1.0.0.zip`，根目录仅有 `plugin.json`、`skills/` 与 `assets/`，不含源码仓库管理文件、缓存、密钥或供应商配置。

1.0.0 正式版流程为：用户主导口头信息，Agent 规划演讲引导；整套版式、可编辑 PowerPoint 母版和全类型示例页先交用户确认；原生 PPT 制作优先，ImgGen 依实际视觉问题按需启用。双宿主独立输入、真实证据保护、整页对照页、可编辑 QA 及模拟观众规则保持有效。

安装后须在新的宿主会话读取已安装 skill，确认与仓库合同一致；仓库/打包验证不代表已完成安装后的行为验证。
